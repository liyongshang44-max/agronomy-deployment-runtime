# ADR-PROD UX-01 — 独立农艺师易用性验证方案

状态：`PROTOCOL_READY / INDEPENDENT_USABILITY_VALIDATION_NOT_EXECUTED`
日期：2026-11-17
产品资格：M1 功能已接受；M2、客户生产资格、商业验证均未接受

## 目的和边界

这是**独立用户易用性测试**，与此前的“功能可以由人工走通”的验收不同。产品组不能因自身完成 Playwright、截图或内部演示而宣称独立易用性通过。测试不能输入真实客户田块、真实研究 PDF、访问凭据或商业敏感数据。参与者只操作本地合成环境。绝不把非权威反馈升级为 ADR 决策。

## 招募和独立性

建议至少 5 名此前未参与 ADR 界面开发的独立农业从业者，优先拥有实际田间技术管理或农艺复核经历。避免仅让工程师照着操作脚本按按钮。至少 1 名参与者需要较少软件系统使用经验；如样本不足，记录局限而不是更改通过标准。研究员不得替参与者选择情景、解释结论或填答。记录征得同意并按需要匿名化。

## 测试任务（每一项均由参与者自行完成）

| 任务 | 成功条件 | 观察点 |
| --- | --- | --- |
| 识别数据性质 | 明确说出演示是合成数据、不是农业作业许可 | 是否误把 DEMO 当正式服务 |
| 找到来源和限制 | 能找出知识的来源条目、主张、版本/精确引用及不能访问的原文 | 是否能区别“知识合格”和“对本田适用” |
| 核对目标上下文 | 指出田块/季节、观测值、原始单位、证据截止与至少一个未知/限制 | 是否误把 UNKNOWN 视为 0 |
| 完成一次真实评估 | 选中现有合格场景、核对两项、触发实际评估 | 是否需要指导/误认为表单可创建新知识 |
| 解释结果 | 用自己的话解释分类、是否需复核及哪些条件不足 | 是否把 NO_REVIEW_CANDIDATE 理解为安全 |
| 记录人工复核 | 正确开始计时、保存反馈，确认它不修改原始科学结论 | 是否误读时长 |
| 导出并定位证据 | 下载报告，找到评估引用、来源和复核内容 | 能否复述报告限制 |
| 断线/恢复 | 模拟暂时不可用后核对同一操作 ID，不创建新身份 | 是否被错误信息诱导反复提交 |

## 可衡量指标与合格标准

逐任务记录：独立完成（无研究员帮助）、有提示完成、失败；任务耗时；错误操作数；求助次数；理解误差；引用发现时间。主观可用性采用统一 5 级评分题：术语清晰、证据可信度表达、异常提示、操作步骤、报告可读性。

候选标准（**尚未验收，非已达成结果**）：

- 关键安全误解为零：无人把 DEMO 当生产许可，把未报告视为“没有”，或把人工反馈当 ADR 权威科学结论。
- 关键路径无研究员指引完成至少 4/5；如样本不同，明确记录原始分母。
- 来源限制、状态与报告可追溯性正确解释至少 4/5。
- 每条 P0/P1 易用性问题均有独立编号、重现步骤、影响、修复及回归证据。
- 未达到标准时不得标记 `USABILITY_ACCEPTED`；可以仍保持 `M1_FUNCTIONAL_IMPLEMENTATION_ACCEPTED`。

## 记录模板

对每位匿名参与者：`participant_code`、农业岗位经验区间、任务编号、开始/结束时间、`UNASSISTED/ASSISTED/FAILED`、关键误解、错误数、原话短摘（获允许时）、问题严重度、观察员、测试源码 SHA。

对每条问题：`UX-ISSUE-N`、影响任务、复现、严重度 P0/P1/P2、源码边界（ADR-PROD 或 WP 接口）、预期行为、修复 Commit、浏览器回归、复测结果。

**当前未知：** 真实独立参与者的完成率、任务时长、满意度、非技术人群中的误解概率。不得补造数字。

## 不变边界

此次 UX 改进只改变文字呈现、信息层级、无障碍导航和报告阅读顺序。不改变科学 Core、Public API、WorkBench 返回结果、身份和权限、精确哈希、幂等写入或独立复核计时。PR #231 的已接受 M1 功能 HEAD 不动，UX 应作为其上游依赖明确的单独后续 PR 测试。正式 M2 / WP 独立验收。
