# ADR Customer Product — ADR-PROD-00/04 integration tranche

This is the independent ADR-PROD customer workbench. The live demonstration runs **real ADR v0.3 Authority Services through real Pilot Host HTTP** but only against the accepted synthetic v0.3 fixture. It is not a customer/production bootstrap, independent scientific authority, or M1/M2 acceptance.

## Start (Node 24)

    npm --prefix apps/adr-product test
    npm --prefix apps/adr-product run demo

Open http://127.0.0.1:3080/ and navigate to 适用性评估. The demo launcher:
1. Initializes the existing qualified ADR v0.3 synthetic acceptance world using the real Pilot Host.
2. Derives immutable Decision/Knowledge/Manifest/RuntimeAuth refs from that world; these are never generated by product code.
3. Binds synthetic, random, in-process-only read/write test credentials to the ADR Host.
4. Starts the true Pilot Host on a loopback ephemeral port, then serves the product BFF on 127.0.0.1:3080.
5. On click, the product BFF submits a new governed ApplicabilityAssessment via Host HTTP with a stable operation ID + Idempotency-Key, then reads the exact Workbench case over Host HTTP.
6. Offers a non-authority review-feedback record with independent demo-only filesystem persistence and an HTML report that the browser can print as PDF.

The demo is only reachable on localhost by default. Neither ADR service tokens nor AuthorizationDecisionAudit refs are taken from browser input. Browser storage contains only a non-authority operation ID; a HttpOnly SameSite demo session cookie and an Origin + CSRF check gate writes. All demo artifacts are explicitly synthetic.

The direct shell without a live synthetic Host is available with:

    npm --prefix apps/adr-product start

This retains static, visibly fictional UI layout fixtures. Formal PILOT mode is fail-closed without WP-supplied bindings:

    ADR_PRODUCT_MODE=PILOT npm --prefix apps/adr-product start

## Present boundaries

- Current interactive demo runs a **new, real ApplicabilityAssessment** using already authorized and qualified synthetic upstream objects. It does **not** yet perform the complete user-editable DecisionProblem -> ContextDatum -> ContextManifest -> Retrieval chain.
- Real Workbench read-model access is exercised through the BFF, and its default escalation queue shows only review-required items.
- The product feedback store is **non-authority** and demo-only, intentionally separate from ADR scientific decisions. It is not an acceptable multi-customer record store.
- A non-201 remote write or lost network response is not called success. The same persisted exact request and key are reused for explicit reconciliation; 409/403 failures do not mint an alternate identity.
- No PDF source read is available without separate WP authority/rights; exported HTML preserves exact hashes and source metadata that the authenticated Host actually provided.
- Existing Core, SDK, frozen Public API, and Pilot Host are not modified.
- The full end-to-end interactive wizard, customer identity, WP interface binding, actual browser automation, M1, M2 and commercial validation remain open.

This is engineering progress, not production qualification. See docs/product/ADR-PROD-00-CONTRACT-V1.md.
